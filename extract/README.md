# 抽出表の形

`table.json` は本体（nanaism/yomiyasu）のどの節から指示文を作ったかを書いた表です。`tools/generate.py` がこの表と本体のチェックアウトから、`yomiyasu-pocket.txt`、`MANIFEST.json`、`SOURCES.md` と README のうち生成する部分（指示文と本体の SKILL.md の字数）を作ります。生成元の本体の版とコミットは MANIFEST.json と SOURCES.md に書きます。本体の SKILL.md の字数は先頭の YAML を含むファイル全体を UTF-8 で読んだ字数（Python の `len`）で、`MANIFEST.json` の `body_skill.characters` にも書きます。

## 上の段

| 名前 | 中身 |
|---|---|
| `format`、`format_version` | `yomiyasu-pocket-extract` と `1` |
| `release` | pocket 自身の版（`1.0.0` のような3つの数）。生成元の本体の版は `body` に書く |
| `body` | 本体の `repository`、`version`（SKILL.md の `metadata.version`）、`tag`、`commit`（40桁） |
| `sections` | 本体の節の一覧 |
| `pieces` | 指示文の部分の一覧。この順につなげたものが指示文になる（区切りの文字は入れない） |

## sections（本体の節）

```json
{"id": "S01", "file": "skills/yomiyasu/SKILL.md", "heading": ["## 1. 基本原則", "### 最優先ルール: 意味の保持"], "sha256": "…"}
```

- `file` は本体の木の中の場所です。
- `heading` は見出しの行そのものを、外側の見出しから順に並べます。`#` の数も含めて、行が一字も違わないものだけに合います。
- コードの囲み（```` ``` ```` や `~~~`）の中の行は、見出しとして数えません。
- 節は見出しの行から、同じ段かそれより上の次の見出しの手前までです（下の段の見出しは節に入ります）。最後の節はファイルの終わりまでです。
- `sha256` は節の中身（見出しの行を含む。UTF-8、改行は LF）のハッシュです。本体の版を替えたときに、中身が変わった節を見つけるために使います。

## pieces（指示文の部分）

書き直した部分は次の形です。

```json
{"id": "T1", "kind": "rewritten", "role": "meaning", "text": "次の文章を、意味を変えずに読みやすい日本語に書き直してください。", "sources": ["S01"]}
```

- `text` は本体の節を短く書き直した文です。`sources` に、元にした節の `id` を書きます。

本体の節をそのまま使う部分は次の形です。

```json
{"id": "T11", "kind": "verbatim", "role": "meaning", "section": "S04"}
```

- 文は本体の節から取ります。見出しの行を除き、前後の空行を落とした中身です。`text` は書きません。
- `sources` を書かなければ、`section` の節だけが出どころになります。
- いまの pocket はこの部分を使っていません。指示文は1段落で400〜500字（生成のスクリプトが止めるのは500字を超えたとき）という決まりがあるので、改行を含む節はそのままでは使えません。

## role（部分の役割）

どの部分にも `role` を書きます。ないときと、下の4つ以外の値のときは、生成が終了コード5で止まります。

| role | 部分 | いまの部分 |
|---|---|---|
| `output` | 返し方。書き直した本文だけを返すように頼む文 | T2 |
| `meaning` | 意味を守る決まり。意味、文の働き、言い切りの強さ、数値、条件、否定を変えない、情報を足さず文を削らない、分からない所を残す、文体と見出しや箇条書きの数と順とかぎかっこの中の言葉を保つ、つながりを変えない文 | T1、T3、T4、T5、T6、T8 |
| `style` | 直す型。AIらしい言い回しの例を挙げて、ふつうの言葉に直すように頼む文と、文末の「と言えるでしょう」の直し方を頼む文 | T7、T10 |
| `restraint` | 直さないもの。「自然な文と慣用句も直さないでください。」 | T9 |

試験（`tests/test_generate.py` の `REQUIRED_RULES`）は、決まりごとに、どの役割の部分のどの文で守るかを正規表現で確かめます。正規表現は文末まで含みます。たとえば「数値を保つ」は、`meaning` の部分に「数値」を含み「変えないでください。」で終わる文があることを求めます。「文を削らない」は、`meaning` の部分に「文も削らないでください。」で終わる文があることを求めます。「本文だけを返す」は、`output` の部分に「本文だけを返し」を含み「付けないでください。」で終わる文があることを求めます。文を「変えてもかまいません。」のような許す言い方に戻すと、どの決まりにも合わなくなります。意味を守る部分と返し方の部分は、どれもこの一覧のどれかの決まりに合わなければなりません。部分を書き直して文末が変わったら、試験の一覧も見直します。

指示文はAIへの依頼の形にそろえます。試験は、どの部分も「ください。」で終わる1文であることを確かめます。「付けません。」「変えません。」のような文末は、書き手が自分のすることを述べた文のようにも読めるので混ぜません。

## 生成のスクリプトの止まり方

| 終了コード | わけ |
|---|---|
| 1 | `--check` で、リポジトリのファイルが生成物と違う。何も書かない |
| 2 | `heading` の見出しが本体にないか、同じ道筋の見出しが2つ以上あって節を決められない。ないものと重なったものを1つの一覧で出し、何も書かない |
| 3 | 節の中身のハッシュが表と違う。「見直しが必要な節」を出し、何も書かない。`--accept-changes` を付けると表を書き直して続ける |
| 4 | 指示文が1段落でないか、500字を超える。何も書かない |
| 5 | 表の形（部分の `role` がないか、知らない値のときを含む）、本体の版、本体のコミット（git のチェックアウトのとき）、README の印のどれかが合わない。何も書かない。コミットの違いだけは、見直したうえで `--accept-changes` を付けると表を書き直して続ける |
