# yomiyasu pocket（よみやす ぽけっと）

## これは何？

yomiyasu-pocket は、AIが書いた日本語を読みやすく整えるための、400〜500字の短い指示文です。[yomiyasu](https://github.com/nanaism/yomiyasu)（以下「本体」）の決まりのうち、意味を守る決まりと、よく使う直し方だけを短く書き直して入れています。

**使うのは [`yomiyasu-pocket.txt`](./yomiyasu-pocket.txt) の指示文だけです。** 同じ文を下の「[指示文](#指示文)」の節にも載せています。AIの指示欄に貼って使うことを考えて作ったもので、スキルの仕組みや検査のスクリプトは使いません。

このリポジトリのほかのファイルは、指示文を本体から作り直したり、指示文を選ぶために測ったりするためのものです。使うときには要りません。

| ファイル・フォルダ | 中身 |
|---|---|
| `yomiyasu-pocket.txt` | 指示文。これをAIの指示欄に貼ります |
| `extract/`、`tools/`、`SOURCES.md`、`MANIFEST.json` | 指示文を本体から作り直すための抽出表、生成のスクリプト、出どころの一覧と記録 |
| `measurements/` | 指示文を選ぶために測った結果 |
| `tests/` | 生成の試験 |

## こんなときに

AIが書く日本語の癖を直したい人のためのものです。

スキルを入れられない人や、入れるほどではない人を考えて作りました。開発者よりも、ふだんの仕事でAIを使う人を主に考えています。

メールアプリやドキュメントのAI校正の指示欄、チャット型AIのカスタム指示のように、指示文を貼る欄に入れて使うことを考えて、400〜500字に収めています。文字数に上限がある欄に入るように、この長さにしました。

## なぜ作ったか

本体は<!-- pocket:body-size:begin -->43,482字の SKILL.md（v2.4.0）<!-- pocket:body-size:end -->と参照ファイル、検査のための Python スクリプトでできています。

AIの機能の中にはスキルを読み込めず、指示欄に文章を直接貼るしかないものがあります。ある利用者はメールの作成画面からAIに文章を整えさせていて、指示を入力欄に貼るしかありません。本体の SKILL.md はその欄に入りきらず、この利用者から「要点だけの400字くらいの版がほしい」という声が届きました。

本体は、以前に短くしたとき、推敲の質が落ち、意味を変える書き直しが戻ってきたことがあります。そのため本体は削らず、別のものとして pocket を作りました。

## 使い方

1. 下の「指示文」をコピーします。
2. AIの指示欄に貼ります。
3. 整えたい文章を渡して、推敲を頼みます。

指示文は、書き直した本文だけを返すようにAIに頼んでいます。返ってきた文で、元の文をそのまま置き換えられるようにするためです。

## 指示文

```text

```

この指示文は `yomiyasu-pocket.txt` にもあります。

## 指示文に入れた決まり

指示文はAIに次のことを頼んでいます。どの文もAIへの依頼の形（〜してください、〜しないでください）で書いています。

- 意味を変えずに書き直す。
- 主張、比重、文の働き（事実、意見、依頼、問いなど）を変えない。
- 言い切りの強さ（推量、可能、許可、義務）を変えない。
- 数値と数え方、固有名詞、日付、条件、否定を変えない。
- 原文にない情報、理由、主語、相手、例を足さず、文も削らない。
- 分からない所は推測で埋めず、原文のまま残す。
- 文体、見出しや箇条書きの数と順、かぎかっこの中の言葉を保つ。
- AIらしい言い回しをふつうの言葉に直す。物を人のように動かす比喩、英語を一語ずつ写した言い回し、英語の術語に当てた漢字1字（版、頭、印）、本文に出てこない比喩の見出し、「重要なのは」などの前置き、意味の増えない「AではなくB」、絵文字、ダッシュ、文末のコロン、間を作るだけの読点を例に挙げています。
- 文末の「と言えるでしょう」は、区分の判断でなければ「でしょう」にする。
- 「仕様変更が」を「仕様が変わると」にするような、つながりを変える書き換えはしない。
- 自然な文と慣用句は直さない。
- 書き直した本文だけを返す。

指示文の各文が本体のどの見出しから来たかは、[SOURCES.md](./SOURCES.md) にあります。抽出の定義は [extract/table.json](./extract/table.json) です。

## 測った結果

本体 v2.4.0 の `tests/corpus/` にある115本の文章（`raw_ai/` 26本、`blacklist_ai/` 24本、`edge_cases/` 49本、`human/` 16本）を、本体 v2.4.0 と pocket の指示文で推敲させ、どちらも3回ずつ流しました。推敲させたのは、本体と pocket のどちらも Claude Code の claude-opus-5-5 で、effort は high です。使える道具と、回数と費用の上限は分けています（[measurements/README.md](./measurements/README.md) の「条件」）。

意味が変わる恐れは本体 v2.4.0 の `yomiyasu_diff.py --fail-on meaning-risk` で、残った候補は `yomiyasu_lint.py` で数えました。

| | pocket | 本体 |
|---|---|---|
| 意味が変わる恐れ（1回目・2回目・3回目） | 2・0・0 | 3・1・0 |
| 意味が変わる恐れ（3回の合計） | 2 | 4 |
| 書き直した文に残った候補（元の文では50） | 41・39・39 | 37・37・37 |
| 元のまま返した文章（115本のうち） | 50・49・53 | 51・52・53 |
| `human/` で書き換えた量の中央値（元の文の空白を除く1,000字あたりの字数） | 88.4・64.8・66.7 | 43.6・40.0・41.8 |

本体は2回目と3回目に、本文のない短い原稿1本（`human/human_oga_01`）を推敲せずに、どう進めるかを尋ねて終えました。本体のこの2回の数は残りの114本のもので、元の文に残った候補は49件、`human/` の中央値は書き直した文のある15本の小さい順の8番目です。ほかの欄の `human/` の中央値は16本の小さい順の9番目です。

pocket の意味が変わる恐れは3回の合計で2件で、本体の4件を超えていません。2件とも1回目に出たもので、どちらも pocket にだけ出た恐れです。1件は「備え、」を「備えて、」にした文で、diff は元の文にもある「担保する」を保証の言い方として数えました。もう1件は「1メソッド」を「1つのメソッド」にした文です。2か所を読むと、どちらも意味は変わっていません。

pocket は本体より、AIらしい言い回しの候補を多く残します（本体の37件に対して39〜41件）。`human/` の文を書き換えた量の中央値は、本体の40.0〜43.6に対して、pocket は64.8〜88.4でした。

この115本の元の文には、英語の術語に当てた漢字1字（版、頭、印）として本体 v2.4.0 の lint が指摘する所が1つもありません。そこで、本体 v2.4.0 の開発で使った類例12本（合成した下書き10本と、実際の下書き2本）を、上と同じ条件で3回ずつ流し、いまの指示文と、本体 v2.2.2 から作った前の指示文を比べました。

- 版、頭、印の直すべき所（1回に15か所、のべ45か所）のうち、出力に残ったのは、いまの指示文で0か所、前の指示文で40か所でした。
- 本体 v2.3.0 までの推敲で直っていた漢字1字（段、窓、帯、床）の、のべ27か所のうち、出力に残ったのは、いまの指示文で0か所、前の指示文で3か所でした。
- 残すべき使い方（第2版、×印、頭上 など）の、のべ39か所のうち、いまの指示文は2か所を書き換え（3回目に「曲の頭」を「曲の始め」に、「部署名の印」を「部署名の目印」に）、前の指示文は0か所でした。

測り方、指示文の候補ごとの比較、類例での比較、pocket にだけ出た恐れの読みは [measurements/README.md](./measurements/README.md) にあります。本体 v2.2.2 から作った前の指示文の測定は [measurements/v2.2.2/README.md](./measurements/v2.2.2/README.md) にあります。

## 本体との違い

| | yomiyasu-pocket | yomiyasu（本体） |
|---|---|---|
| 長さ | 400〜500字の指示文1つ | <!-- pocket:body-size-row:begin -->43,482字の SKILL.md（v2.4.0）<!-- pocket:body-size-row:end -->と参照ファイル |
| 検査 | なし | lint、diff、最終稿の照合 |

pocket には検査のスクリプトがありません。書き直した文の意味がずれていないかを、仕組みで確かめる手段はありません。

## どちらを使えばいいか

スキルを読み込めるAIを使っているなら、本体をおすすめします。

仕様書や契約書、公開する記事のように、意味を守る検査が要る文章にも、本体をおすすめします。

pocket は、スキルを読み込めず指示欄に貼るしかないときや、短い文章を手軽に整えたいときに使ってください。

## 作り直すとき

指示文は本体から次の手順で作り直せます。抽出表 `extract/table.json` は、本体のファイルの場所と見出しで節を指し、節ごとに中身の sha256 を持っています。生成には Python 3.9 以上の標準ライブラリだけを使います。

1. 本体の新しいバージョンのタグを `body/` に取り出します（下の例は v2.4.0 です）。

   ```bash
   git clone --depth 1 --branch v2.4.0 https://github.com/nanaism/yomiyasu body
   ```

2. 本体のバージョンが変わったら、`extract/table.json` の `body`（version、tag、commit）を書き直します。`release` は pocket 自身のバージョン（`1.1.0` のような3つの数）です。生成元の本体のバージョンとコミットは、`MANIFEST.json` と `SOURCES.md` に書き出されます。
3. 生成します。

   ```bash
   python3 tools/generate.py --body body
   ```

   - 終了コード 2: 抽出表が指す見出しが本体にないか、同じ道筋の見出しが2つ以上あって節を決められません。ないものと重なったものを1つの一覧で出し、何も書かずに止まります。抽出表の見出しを直します。
   - 終了コード 3: 中身が変わった節を「見直しが必要な節」として出し、何も書かずに止まります。その節を読んで指示文の部分を見直し、`--accept-changes` を付けて作り直すと、抽出表のハッシュが書き直されます。
   - 終了コード 4: 指示文が1段落でないか、500字を超えています。
   - 終了コード 5: 抽出表の形（部分の `role` がないか、知らない値のときを含みます）、本体のバージョン、本体のコミット、README の目印のコメントのどれかが合いません。何も書かずに止まります。本体のコミットの違いだけは、見直したうえで `--accept-changes` を付けると抽出表が書き直されます。

4. 確かめます。

   ```bash
   python3 tools/generate.py --body body --check
   BODY_DIR=body python3 -m unittest discover -s tests -v
   ```

   - 終了コード 1: `--check` で、リポジトリのファイルが生成物と違います。手順3で作り直します。

`yomiyasu-pocket.txt`、`MANIFEST.json`、`SOURCES.md` と、この README の指示文と本体の SKILL.md の字数は、生成のスクリプトが書きます。手で直さないでください。
