# yomiyasu-pocket

## これは何？

yomiyasu-pocket は、AIが書いた日本語を読みやすく整えるための、400字以内の短い指示文です。

AIの指示欄に貼って使うことを考えて作りました。スキルやファイルは使いません。

[yomiyasu](https://github.com/nanaism/yomiyasu)（以下「本体」）の決まりのうち、意味を守る決まりと、よく使う直し方だけを短く書き直して入れています。

版 2.1.1-r1（本体 v2.1.1、コミット fbe02c93877d697cc53d9377b7a45dd8a1dd99b3 から生成）

## こんなときに

AIが書く日本語の癖を直したい人のためのものです。

スキルを入れられない人や、入れるほどではない人を考えて作りました。開発者よりも、ふだんの仕事でAIを使う人を主に考えています。

メールアプリやドキュメントのAI校正の指示欄、チャット型AIのカスタム指示のように、指示文を貼る欄に入れて使うことを考えて、400字以内に収めています。文字数に上限がある欄を考えて、この長さにしました。

## なぜ作ったか

本体は、<!-- pocket:body-size:begin -->41,445字の SKILL.md（v2.1.1）<!-- pocket:body-size:end -->と参照ファイル、検査のための Python スクリプトでできています。

AIの機能の中には、スキルを読み込めず、指示欄に文章を直接貼るしかないものがあります。ある利用者は、メールの作成画面からAIに文章を整えさせていて、指示を入力欄に貼るしかありません。本体の SKILL.md はその欄に入りきらず、この利用者から「要点だけの400字くらいの版がほしい」という声が届きました。

本体は、以前に短くしたとき、推敲の質が落ち、意味を変える書き直しが戻ってきたことがあります。そのため本体は削らず、別のものとして pocket を作りました。

## 使い方

1. 下の「指示文」をコピーします。
2. AIの指示欄に貼ります。
3. 整えたい文章を渡して、推敲を頼みます。

指示文は、書き直した本文だけを返すようにAIに頼んでいます。返ってきた文で、元の文をそのまま置き換えられるようにするためです。

## 指示文

<!-- pocket:instruction:begin -->
```text
次の文章を、意味を変えずに読みやすい日本語に書き直してください。返すのは書き直した本文だけにし、説明や前置きは付けません。主張、比重、文の働き（事実、意見、依頼、予定）、言い切りの強さ（推量、可能、許可、義務）、数値、固有名詞、日付、条件、否定は変えません。原文にない情報、理由、主語、例は足しません。分からない所は推測で埋めず、原文のまま残します。文体（です・ます、だ・である）と、見出しや箇条書きの数と順は保ちます。AIらしい言い回しはふつうの言葉に直します。物や概念を人のように動かす比喩、「重要なのは」のような前置き、意味の増えない「AではなくB」、言い直すだけのまとめ、絵文字、ダッシュ、文末のコロン、間を作るだけの読点です。自然な文と慣用句は直しません。
```
<!-- pocket:instruction:end -->

この指示文は `pocket.txt` にもあります。

## 指示文に入れた決まり

指示文は、AIに次のことを頼んでいます。

- 意味を変えずに書き直す。
- 原文にない情報を足さない。
- 言い切りの強さ（推量、可能、許可、義務）を変えない。
- 数値、条件、否定などを変えない。
- AIらしい言い回しをふつうの言葉に直す。
- 書き直した本文だけを返す。

指示文の各文が本体のどの見出しから来たかは、[SOURCES.md](./SOURCES.md) にあります。抽出の定義は [extract/table.json](./extract/table.json) です。

## 本体との違い

| | yomiyasu-pocket | yomiyasu（本体） |
|---|---|---|
| 長さ | 400字以内の指示文1つ | <!-- pocket:body-size-row:begin -->41,445字の SKILL.md（v2.1.1）<!-- pocket:body-size-row:end -->と参照ファイル |
| 検査 | なし | lint、diff、最終稿の照合 |

pocket には検査のスクリプトがありません。書き直した文の意味がずれていないかを、仕組みで確かめる手段はありません。

## どちらを使えばいいか

スキルを読み込めるAIを使っているなら、本体をおすすめします。

仕様書や契約書、公開する記事のように、意味を守る検査が要る文章にも、本体をおすすめします。

pocket は、スキルを読み込めず指示欄に貼るしかないときや、短い文章を手軽に整えたいときに使ってください。

## 作り直すとき

指示文は、本体の版ごとに作り直します。抽出表 `extract/table.json` は、本体のファイルの場所と見出しで節を指し、節ごとに中身の sha256 を持っています。生成には Python 3.9 以上の標準ライブラリだけを使います。

1. 本体の新しい版のタグを `body/` に取り出します（下の例は v2.1.1 です）。

   ```bash
   git clone --depth 1 --branch v2.1.1 https://github.com/nanaism/yomiyasu body
   ```

2. 本体の版が変わったら、`extract/table.json` の `body`（version、tag、commit）と `release` を書き直します。`release` は、本体の版とこちらの連番を並べた `2.1.1-r1` の形です。
3. 生成します。

   ```bash
   python3 tools/generate.py --body body
   ```

   - 終了コード 2: 抽出表が指す見出しが本体にないか、同じ道筋の見出しが2つ以上あって節を決められません。ないものと重なったものを1つの一覧で出し、何も書かずに止まります。抽出表の見出しを直します。
   - 終了コード 3: 中身が変わった節を「見直しが必要な節」として出し、何も書かずに止まります。その節を読んで指示文の部分を見直し、`--accept-changes` を付けて作り直すと、抽出表のハッシュが書き直されます。
   - 終了コード 4: 指示文が1段落でないか、400字を超えています。
   - 終了コード 5: 抽出表の形（部分の `role` がないか、知らない値のときを含みます）、本体の版、本体のコミット、README の印のどれかが合いません。何も書かずに止まります。本体のコミットの違いだけは、見直したうえで `--accept-changes` を付けると抽出表が書き直されます。

4. 確かめます。

   ```bash
   python3 tools/generate.py --body body --check
   BODY_DIR=body python3 -m unittest discover -s tests -v
   ```

   - 終了コード 1: `--check` で、リポジトリのファイルが生成物と違います。手順3で作り直します。

`pocket.txt`、`MANIFEST.json`、`SOURCES.md` と、この README の版の行、指示文、本体の SKILL.md の字数は、生成のスクリプトが書きます。手で直さないでください。
