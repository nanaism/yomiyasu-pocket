# yomiyasu-pocket（よみやす ぽけっと）

## これは何？

yomiyasu-pocket は、AIが書いた日本語を読みやすく整えるための、400〜500字の短い指示文です。[yomiyasu](https://github.com/nanaism/yomiyasu)（以下「本体」）の決まりのうち、意味を守る決まりと、よく使う直し方だけを短く書き直して入れています。

**使うのは [`yomiyasu-pocket.txt`](./yomiyasu-pocket.txt) の指示文だけです。** 同じ文を、下の「[指示文](#指示文)」の節にも載せています。AIの指示欄に貼って使うことを考えて作ったもので、スキルの仕組みや検査のスクリプトは使いません。

このリポジトリのほかのファイルは、指示文を本体から作り直したり、指示文を選ぶために測ったりするためのものです。使うときには要りません。

| ファイル・フォルダ | 中身 |
|---|---|
| `yomiyasu-pocket.txt` | 指示文。これをAIの指示欄に貼ります |
| `extract/`、`tools/`、`SOURCES.md`、`MANIFEST.json` | 指示文を本体から作り直すための抽出表、生成のスクリプト、出どころの一覧と記録 |
| `measurements/` | 指示文を選ぶために測った結果 |
| `tests/` | 生成の試験 |

## こんなときに

AIが書く日本語の癖を直したい人のためのものです。

スキルを入れられない人や、入れるほどではない人を考えて作りました。開発者よりも、ふだんの仕事でAIを使う人を主に考えています。

メールアプリやドキュメントのAI校正の指示欄、チャット型AIのカスタム指示のように、指示文を貼る欄に入れて使うことを考えて、400〜500字に収めています。文字数に上限がある欄を考えて、この長さにしました。

## なぜ作ったか

本体は、<!-- pocket:body-size:begin -->41,445字の SKILL.md（v2.1.1）<!-- pocket:body-size:end -->と参照ファイル、検査のための Python スクリプトでできています。

AIの機能の中には、スキルを読み込めず、指示欄に文章を直接貼るしかないものがあります。ある利用者は、メールの作成画面からAIに文章を整えさせていて、指示を入力欄に貼るしかありません。本体の SKILL.md はその欄に入りきらず、この利用者から「要点だけの400字くらいの版がほしい」という声が届きました。

本体は、以前に短くしたとき、推敲の質が落ち、意味を変える書き直しが戻ってきたことがあります。そのため本体は削らず、別のものとして pocket を作りました。

## 使い方

1. 下の「指示文」をコピーします。
2. AIの指示欄に貼ります。
3. 整えたい文章を渡して、推敲を頼みます。

指示文は、書き直した本文だけを返すようにAIに頼んでいます。返ってきた文で、元の文をそのまま置き換えられるようにするためです。

## 指示文

<!-- pocket:instruction:begin -->
```text
次の文章を、意味を変えずに読みやすい日本語に書き直してください。書き直した本文だけを返し、説明や前置きは付けないでください。主張、比重、文の働き（事実、意見、依頼、問い、予定）、言い切りの強さ（推量、可能、許可、義務）、数値、固有名詞、日付、条件、否定は変えないでください。原文にない情報、理由、主語、例は足さず、文も削らないでください。分からない所は推測で埋めず、原文のまま残してください。文体（です・ます、だ・である）、見出しや箇条書きの数と順、かぎかっこの中の言葉も保ってください。物や概念を人のように動かす比喩、「重要なのは」のような前置き、意味の増えない「AではなくB」、絵文字、ダッシュ、文末のコロン、間を作るだけの読点など、AIらしい言い回しはふつうの言葉に直してください。ただし、「仕様変更が」を「仕様が変わると」にするような、つながりを変える書き換えはしないでください。自然な文と慣用句も直さないでください。
```
<!-- pocket:instruction:end -->

この指示文は `yomiyasu-pocket.txt` にもあります。

## 指示文に入れた決まり

指示文は、AIに次のことを頼んでいます。どの文も、AIへの依頼の形（〜してください、〜しないでください）で書いています。

- 意味を変えずに書き直す。
- 主張、比重、文の働き（事実、意見、依頼、問いなど）を変えない。
- 言い切りの強さ（推量、可能、許可、義務）を変えない。
- 数値、固有名詞、日付、条件、否定を変えない。
- 原文にない情報、理由、主語、例を足さず、文も削らない。
- 分からない所は推測で埋めず、原文のまま残す。
- 文体、見出しや箇条書きの数と順、かぎかっこの中の言葉を保つ。
- AIらしい言い回しをふつうの言葉に直す。物や概念を人のように動かす比喩、「重要なのは」のような前置き、意味の増えない「AではなくB」、絵文字、ダッシュ、文末のコロン、間を作るだけの読点を例に挙げています。
- ただし、「仕様変更が」を「仕様が変わると」にするような、つながりを変える書き換えはしない。
- 自然な文と慣用句は直さない。
- 書き直した本文だけを返す。

指示文の各文が本体のどの見出しから来たかは、[SOURCES.md](./SOURCES.md) にあります。抽出の定義は [extract/table.json](./extract/table.json) です。

## 測った結果

本体 v2.1.1 の `tests/corpus/` にある115本の文章（`raw_ai/` 26本、`blacklist_ai/` 24本、`edge_cases/` 49本、`human/` 16本）を、本体 v2.1.1 と pocket の指示文で推敲させ、どちらも3回ずつ流しました。推敲させたのは Codex CLI の gpt-6-astra で、effort は high です。本体と pocket で同じモデルと effort を使いました。速さの指定は、pocket の3回と本体の3回目がどれも既定の速さで、本体の1回目と2回目は速い応答の指定（ultrafast）でした。

意味が変わる恐れは本体 v2.1.1 の `yomiyasu_diff.py --fail-on meaning-risk` で、残った候補は `yomiyasu_lint.py` で数えました。

| | pocket | 本体 |
|---|---|---|
| 意味が変わる恐れ（1回目・2回目・3回目） | 2・3・1 | 4・3・3 |
| 意味が変わる恐れ（3回の合計） | 6 | 10 |
| 書き直した文に残った候補（元の文では49） | 42・42・42 | 35・35・35 |
| 元のまま返した文章（115本のうち） | 48・48・46 | 43・42・43 |
| `human/` の16本で書き換えた量の中央値（元の文の空白を除く1,000字あたりの字数。16本の小さい順の9番目） | 67.4・44.8・51.2 | 49.0・48.2・41.8 |

上の表の数字は、文末を依頼の形にそろえる前の指示文（候補 P2）で測ったものです。この節のほかの数字と読みも、P2 で測ったものです。いまの指示文（候補 Q1）は、P2 の決まりの中身を変えずに、文末をAIへの依頼の形にそろえたものです。あわせて、AIらしい言い回しの例を1文にまとめ、つながりの決まりの前に「ただし、」を足しました。Q1 は115本のうち34本を1回流し、その34本で意味が変わる恐れは0件でした（[measurements/README.md](./measurements/README.md) の「いまの指示文（Q1）」の節）。

同じ既定の速さで流した本体の3回目（3件）と比べても、pocket の各回（2件、3件、1件）は超えていません。

pocket にだけ出た意味の恐れ5件は、1件ずつ読みました。diff が数えた所では、どれも意味は変わっていません。4件は数の言い方の替えで（「一個ずつ」を「一つずつ」にしたものが3件、「1メソッド」を「1つのメソッド」にしたものが1件）、1件は2行に分けて書かれた問いを1文につないだものです。ただし diff が数えない所で、pocket は書き手の言い回しも替えていました。「1メソッド」の次の文では「全部このメソッドを触る」を「いずれもこのメソッドを修正する」にしていて、「触る」が「修正する」に狭まっています。`human/human_oga_08` では3回とも、書き手の「全体の地図を頭の中に作る」「明示的に伝え」「前に進みます」を別の言い方に替えていました。本体の3回は、どれも元のまま残しています。

pocket は本体より、AIらしい言い回しの候補を多く残します（3回とも、本体35件に対して42件）。`human/` の文を書き換えた量の中央値は、本体の41.8〜49.0に対して、pocket は44.8〜67.4でした。

測り方、指示文の候補ごとの比較、残した決まりと外した決まりの理由、5件の読みは [measurements/README.md](./measurements/README.md) にあります。

## 本体との違い

| | yomiyasu-pocket | yomiyasu（本体） |
|---|---|---|
| 長さ | 400〜500字の指示文1つ | <!-- pocket:body-size-row:begin -->41,445字の SKILL.md（v2.1.1）<!-- pocket:body-size-row:end -->と参照ファイル |
| 検査 | なし | lint、diff、最終稿の照合 |

pocket には検査のスクリプトがありません。書き直した文の意味がずれていないかを、仕組みで確かめる手段はありません。

## どちらを使えばいいか

スキルを読み込めるAIを使っているなら、本体をおすすめします。

仕様書や契約書、公開する記事のように、意味を守る検査が要る文章にも、本体をおすすめします。

pocket は、スキルを読み込めず指示欄に貼るしかないときや、短い文章を手軽に整えたいときに使ってください。

## 作り直すとき

指示文は、本体の版が上がったときに作り直します。抽出表 `extract/table.json` は、本体のファイルの場所と見出しで節を指し、節ごとに中身の sha256 を持っています。生成には Python 3.9 以上の標準ライブラリだけを使います。

1. 本体の新しい版のタグを `body/` に取り出します（下の例は v2.1.1 です）。

   ```bash
   git clone --depth 1 --branch v2.1.1 https://github.com/nanaism/yomiyasu body
   ```

2. 本体の版が変わったら、`extract/table.json` の `body`（version、tag、commit）を書き直します。`release` は pocket 自身の版（`1.0.0` のような3つの数）で、指示文や生成元の本体の版が変わったときに上げます。生成元の本体の版とコミットは、`MANIFEST.json` と `SOURCES.md` に書き出されます。
3. 生成します。

   ```bash
   python3 tools/generate.py --body body
   ```

   - 終了コード 2: 抽出表が指す見出しが本体にないか、同じ道筋の見出しが2つ以上あって節を決められません。ないものと重なったものを1つの一覧で出し、何も書かずに止まります。抽出表の見出しを直します。
   - 終了コード 3: 中身が変わった節を「見直しが必要な節」として出し、何も書かずに止まります。その節を読んで指示文の部分を見直し、`--accept-changes` を付けて作り直すと、抽出表のハッシュが書き直されます。
   - 終了コード 4: 指示文が1段落でないか、500字を超えています。
   - 終了コード 5: 抽出表の形（部分の `role` がないか、知らない値のときを含みます）、本体の版、本体のコミット、README の印のどれかが合いません。何も書かずに止まります。本体のコミットの違いだけは、見直したうえで `--accept-changes` を付けると抽出表が書き直されます。

4. 確かめます。

   ```bash
   python3 tools/generate.py --body body --check
   BODY_DIR=body python3 -m unittest discover -s tests -v
   ```

   - 終了コード 1: `--check` で、リポジトリのファイルが生成物と違います。手順3で作り直します。

`yomiyasu-pocket.txt`、`MANIFEST.json`、`SOURCES.md` と、この README の指示文と本体の SKILL.md の字数は、生成のスクリプトが書きます。手で直さないでください。
