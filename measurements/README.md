# 測定の結果

本体（yomiyasu v3.0.0）と pocket の指示文に同じ文章を推敲させ、本体 v3.0.0 の検査で数えた結果です。いまの指示文は候補 F1 です。

本体 v2.5.0 から指示文を作ったときの測定は [v2.5.0/README.md](./v2.5.0/README.md) に、本体 v2.4.0、v2.2.2、v2.1.1 から作ったときの測定は [v2.4.0/README.md](./v2.4.0/README.md)、[v2.2.2/README.md](./v2.2.2/README.md)、[v2.1.1/README.md](./v2.1.1/README.md) にあります。指示文の決まりの多くはそのときの比較で選んだものです。

## 条件

- 推敲させた道具: Claude Code 2.1.314（`claude --print`）
- モデル: claude-opus-5-5
- effort: high（`--effort high`）
- service_tier: Claude Code の記録ではどの回も standard でした。
- 本体と pocket で共通の設定と、本体だけ、pocket だけの設定は、本体 v2.4.0 の測定（[v2.4.0/README.md](./v2.4.0/README.md) の「条件」）と同じです。1本ごとに空の作業場所を作り、1回の依頼で1本を推敲させました。

## 入力

本体 v3.0.0 の `tests/corpus/` の文章のうち、本体 v2.4.0 の測定と同じ115本です。v2.5.0 と v3.0.0 で `edge_cases/` に足された18本は入れていません。115本は v3.0.0 の同じ名前のファイルと1バイトも違いません。

| 群 | 本数 |
|---|---|
| `raw_ai/` | 26 |
| `blacklist_ai/` | 24 |
| `edge_cases/` | 49 |
| `human/` | 16 |

- 本体: 作業場所の `.claude/skills/yomiyasu` に本体 v3.0.0 の `skills/yomiyasu` を置き、`draft.md` に原稿を置いて、「draft.md を yomiyasu で読みやすくして、結果を out.md に書いてください。」と頼みました。`out.md` を書き直した文とします。345回とも、使われたスキルは yomiyasu だけでした。
- pocket: 指示文、空行、原稿を1つの依頼にして渡しました。最後の返事を書き直した文とします。返事全体がコードの囲みに入っていたら中身を取り出す決まりにしましたが、囲みに入った返事はありませんでした。スキルは置かず、道具はすべて外しています。

## 数え方

本体 v2.4.0 の測定と同じです。Claude Code の結果を [tools/run.py](./tools/run.py) と同じフォルダの形に並べ、[tools/score.py](./tools/score.py) と [tools/aggregate.py](./tools/aggregate.py) で、本体 v3.0.0 の検査を使って数えました。

- 意味が変わる恐れ: 元の原稿と書き直した文を、本体 v3.0.0 の `yomiyasu_diff.py --fail-on meaning-risk`（文書の種類は指定しない）で比べた `fail_on_meaning_risk_count` です。
- 残った候補: 書き直した文を本体 v3.0.0 の `yomiyasu_lint.py` で調べた候補の数です（error、warn、info の合計）。括弧の中は warn と error だけの数です。元の原稿115本では50件です。
- 元のまま: 前後の空白を除いて、書き直した文が元の原稿と同じ文章の数です。
- 書き換えた量: `difflib.SequenceMatcher` の opcodes のうち、同じでない部分ごとに元と後の長いほうの字数を足し、元の原稿の空白を除いた字数1,000字あたりにした値です。`human/` の16本の中央値（小さい順に並べた9番目）を載せます。

合格の線は、pocket の意味が変わる恐れの3回の合計が、本体の3回の合計を超えないことです。この測定を始める前に決めました。F1 は3回の合計が1件で、本体の5件を超えていません。

本体の5件は次のとおりです。

- `blacklist_ai/07_code_review_sonnet_casual` で、「1メソッドに並んでいます」の文を「`OrderService.checkout` という1つのメソッドに、…」と組み替え、diff が数の言い方が消えたとして数えたもの（number / lost。1回目、2回目、3回目）

pocket の1件は2回目の `blacklist_ai/07_code_review_sonnet_casual` で「1メソッド」を「1つのメソッド」にしたもの（number / lost）です。本体も3回とも、同じ原稿で同じ種類の恐れを出しているので、「pocket にだけ出た恐れ」には入りません。

## 指示文の候補

候補の文は [variants.json](./variants.json) にあります。字数は Python の `len` で数えました。

| 候補 | 中身 | 字数 | 回数 | 意味が変わる恐れ | 残った候補 | 元のまま | `human/` の書き換えた量の中央値 |
|---|---|---:|---:|---|---|---|---|
| F0 | 本体 v2.5.0 から作った指示文（v2.5.0 の記録の E1）と同じ文。元にした節だけを v3.0.0 の見出しに付け替えた | 500 | 1 | 0 | 42 | 54 | 64.8 |
| F1 | F0 の「文体（です・ます、だ・である）」の括弧の例を外し、「漢語と和語の選び方も保ってください」を足す（いまの指示文） | 497 | 3 | 0、1、0 | 42、42、41 | 62、63、60 | 52.5、47.5、41.5 |

- 本体 v3.0.0 では SKILL.md を作り直し、抽出表が指していた節のうち6つの見出しが変わりました。「Step 2: 文章の書き直し」は「Step 2: 上から読み、1か所ずつ直す」に、「擬人化の解消」と「比喩動詞の具体化」は「比喩動詞の具体化と擬人化の解消」に、「装飾記号の排除と太字の表示」と「コピー調の抑制」は「装飾記号の排除と太字の表示、コピー調の抑制」に、calques.md の「4つの型」は「5つの型」になりました。指示文の各文の決まりはどれも v3.0.0 の節にそのまま当てはまるので、F0 は文を変えずに元にした節だけを付け替えました。
- 本体 v3.0.0 で足された決まりのうち、「漢語と和語の選び方は原文のままにします」を F1 に入れました。ある利用者から、推敲で「確認」を「確かめ」にするように漢語を和語に開きすぎるという指摘があって、本体に足された決まりです。500字に収めるため、「文体」の括弧の例（です・ます、だ・である）を外しました。
- 115本の1回目では、意味が変わる恐れはどちらも0件で、F1 のほうが書き換えた量が少なく、元のまま返した文章が多くなりました。漢語を和語に開いた所も、下の節のとおり F1 のほうが少なかったので、F1 を3回流しました。

ほかの足された決まりは次の理由で入れていません。

- 本文を一括の置換で直さない: pocket の指示文は道具を使わせません。
- 上から1回読み、読み手が止まる所を書き出してから直す: 推敲の手順で、500字に入れる形で書けません。
- 太字のラベルを文に入れるとき、ラベルの語を落とさず、働きが変わるならラベルとコロンを残す: 500字に入れる形で書けません。
- 見出しから本文へ移すとき、見出しの語を落とさない: 同じです。
- 「静かに」を「気づかないうちに」に言い換えるのは、知らせが出ないことをぼかしたときだけにする: 同じです。
- 「AではなくB」の「なく」のあとの読点を外す: 指示文の「間を作るだけの読点」と「読点は足さないでください」で扱います。
- 直訳語の5つ目の型（英語の術語に当てた2字以上の名詞）: 指示文の「英語を一語ずつ写した言い回し」で扱います。

## 漢語を和語に開いた所

本体の開発で、利用者の指摘を確かめたときと同じ数え方で数えました。原稿と書き直した文を文字の difflib で比べ、置き換えの区間の元の側に表の漢語があり、新しい側にその和語の言い方があるものを1件と数えます。1つの書き換えが置き換えの区間2つに分かれると、2件に数えます。表は確認、使用、停止、現在、実施、発生、変更、調査、導入、増加など37語の漢語と、その和語の言い方です。数と置き換えた文は [kango.json](./kango.json) にあります。

| 条件と回 | 115本で漢語を和語に開いた件数 | 2件に数えた書き換えを1つにした数 |
|---|---:|---:|
| 本体 1回目・2回目・3回目 | 4・3・0 | 3・2・0 |
| pocket（F0）1回目 | 14 | 12 |
| pocket（F1）1回目・2回目・3回目 | 4・1・0 | 3・1・0 |

F0 の14件は、「発生」を「起きる」、「確認」を「確かめる」、「調査」を「調べる」、「実施」を「行う」、「導入」を「入れる」、「増加」を「増える」、「変更が入る」を「変わる」、「送信」を「送る」にしたものです。`human/human_doc_10` の「導入」と `human/human_doc_16` の「変更が入る」は、どちらも1つの書き換えが2件に数えられています。F1 の5件は、「調査」を「調べる」にしたものが1件、「確認」を「確かめる」にしたものが2件と、`human/human_doc_16` の「既存動作に変更が入る」を「既存の動作が変わる」にした1つの書き換え（2件）です。本体の7件のうち4件も、`human/human_doc_16` の同じ所の書き換え（1回目と2回目に1つずつ）です。

本体の開発で作られた、漢語の多い業務・技術の合成の下書き8本（このリポジトリには入れていません）でも、F0 と F1 を2回ずつ流しました。漢語を和語に開いた件数は、F0 が1件と0件、F1 が0件と0件でした。
