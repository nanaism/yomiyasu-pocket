# 本体 v2.5.0 で測った結果

この記録は本体 v2.5.0 から指示文を作ったときの測定です。いまの指示文は本体 v3.0.0 から作り直し、[../README.md](../README.md) の測定で選びました。

本体（yomiyasu v2.5.0）と pocket の指示文に同じ文章を推敲させ、本体 v2.5.0 の検査で数えた結果です。このときの指示文は候補 E1 です。

本体 v2.4.0 から指示文を作ったときの測定は [v2.4.0/README.md](../v2.4.0/README.md) に、本体 v2.2.2 と v2.1.1 から作ったときの測定は [v2.2.2/README.md](../v2.2.2/README.md) と [v2.1.1/README.md](../v2.1.1/README.md) にあります。指示文の決まりの多くは、そのときの比較で選んだものです。

## 条件

- 推敲させた道具: Claude Code 2.1.310（`claude --print`）
- モデル: claude-opus-5-5
- effort: high（`--effort high`）
- service_tier: Claude Code の記録ではどの回も standard でした。
- 本体と pocket で共通の設定と、本体だけ、pocket だけの設定は、本体 v2.4.0 の測定（[v2.4.0/README.md](../v2.4.0/README.md) の「条件」）と同じです。1本ごとに空の作業場所を作り、1回の依頼で1本を推敲させました。

## 入力

本体 v2.5.0 の `tests/corpus/` の文章のうち、本体 v2.4.0 の測定と同じ115本です。v2.5.0 で `edge_cases/` に足された6本は入れていません。115本は v2.5.0 の同じ名前のファイルと1バイトも違いません。

| 群 | 本数 |
|---|---|
| `raw_ai/` | 26 |
| `blacklist_ai/` | 24 |
| `edge_cases/` | 49 |
| `human/` | 16 |

- 本体: 作業場所の `.claude/skills/yomiyasu` に本体 v2.5.0 の `skills/yomiyasu` を置き、`draft.md` に原稿を置いて、「draft.md を yomiyasu で読みやすくして、結果を out.md に書いてください。」と頼みました。`out.md` を書き直した文とします。345回とも、使われたスキルは yomiyasu だけでした。
- pocket: 指示文、空行、原稿を1つの依頼にして渡しました。最後の返事を書き直した文とします。返事全体がコードの囲みに入っていたら中身を取り出す決まりにしましたが、囲みに入った返事はありませんでした。スキルは置かず、道具はすべて外しています。

## 数え方

本体 v2.4.0 の測定と同じです。Claude Code の結果を [tools/run.py](../tools/run.py) と同じフォルダの形に並べ、[tools/score.py](../tools/score.py) と [tools/aggregate.py](../tools/aggregate.py) で、本体 v2.5.0 の検査を使って数えました。

- 意味が変わる恐れ: 元の原稿と書き直した文を、本体 v2.5.0 の `yomiyasu_diff.py --fail-on meaning-risk`（文書の種類は指定しない）で比べた `fail_on_meaning_risk_count` です。
- 残った候補: 書き直した文を本体 v2.5.0 の `yomiyasu_lint.py` で調べた候補の数です（error、warn、info の合計）。括弧の中は warn と error だけの数です。元の原稿115本では50件です。
- 元のまま: 前後の空白を除いて、書き直した文が元の原稿と同じ文章の数です。
- 書き換えた量: `difflib.SequenceMatcher` の opcodes のうち、同じでない部分ごとに元と後の長いほうの字数を足し、元の原稿の空白を除いた字数1,000字あたりにした値です。`human/` の16本の中央値（小さい順に並べた9番目）を載せます。

## 本体と pocket（E1）

どちらも115本を3回ずつ流しました。書き直した文はどの回も115本すべてで得られました。

| 条件と回 | 意味が変わる恐れ | 恐れの出た文章 | 残った候補 | 元のまま | `human/` の書き換えた量の中央値 |
|---|---:|---:|---:|---:|---:|
| 本体 1回目 | 4 | 4 | 34（22） | 50 | 49.8 |
| 本体 2回目 | 1 | 1 | 35（21） | 51 | 38.3 |
| 本体 3回目 | 1 | 1 | 37（23） | 53 | 36.2 |

| pocket（E1）2回目 | 2 | 2 | 40（27） | 56 | 68.7 |
| pocket（E1）3回目 | 0 | 0 | 42（27） | 49 | 56.2 |

合格の線は、pocket の意味が変わる恐れの3回の合計が、本体の3回の合計を超えないことです。この測定を始める前に決めました。E1 は3回の合計が2件で、本体の6件を超えていません。

本体の6件は次のとおりです。

- `blacklist_ai/07_code_review_sonnet_casual` で、2つ目の提案の「…見えないようにします」を「…見えないようにしてください」にした文の種類の変化（1回目と2回目）
- `human/human_doc_16` で、「週に1回木曜日に」を「毎週木曜日に」にして数の言い方が消えたもの（number / lost。1回目と3回目）
- `human/human_oga_04` で、2行に分けて書かれた問いを1文につないだもの（1回目）
- `raw_ai/04_slack_announce_sonnet_default` で、「お願いしたいことは3点あります。」を「次の3点をお願いします。」にした文の種類の変化（1回目）

pocket は本体より書き換える量が多く、`human/` の書き換えた量の中央値は、E1 のどの回も本体のどの回より大きくなりました。

## 指示文の候補

候補の文は [variants.json](./variants.json) にあります。字数は Python の `len` で数えました。

| 候補 | 中身 | 字数 | 回数 | 意味が変わる恐れ | 残った候補 | 元のまま | `human/` の書き換えた量の中央値 |
|---|---|---:|---:|---|---|---|---|
| E0 | 本体 v2.4.0 から作った指示文（pocket 1.1.0 の D2） | 498 | 1 | 1 | 43 | 59 | 67.0 |
| E1 | E0 に、推敲で読点を足さない決まりと、指定の見出しの形を保つ決まりを足す（このときの指示文） | 500 | 3 | 0、2、0 | 41、40、42 | 54、56、49 | 73.4、68.7、56.2 |
| E2 | E0 に、推敲で読点を足さない決まりだけを足す | 497 | 1 | 1 | 40 | 54 | 66.7 |

- 本体 v2.5.0 で足された決まりのうち、指示文に入れたのは、推敲で読点を足さないこと（「読点は足さないでください」）と、依頼で指定された見出しの形を保つこと（「指定の見出しの形」）の2つです。依頼で指定されたまとめの節やページは、もとからある「文も削らないでください」で残ります。
- コードやシステムを説明する文書の擬人化は、コードや資料から動作が分かるときだけ書き直し、分からなければ残して尋ねる決まりです。pocket には書き手に尋ねる欄がありません。分からない所を原文のまま残す決まりは、もとからある「分からない所は推測で埋めず、原文のまま残してください」に当たります。
- 否定で終わる定義文と、漢語の名詞で動作を省いた文の決まりは入れていません。どちらも、原文や資料から分かるときだけ書き直す条件が要り、500字に入れる余地がないためです。
- AI の文章によく出る言い回し（「〜に潜むリスク」「〜という見立てです」など）も入れていません。本体ではどれも、指摘が出ただけでは直さず、足りないもの（判断した人、潜むものの中身）が原文、依頼、資料、文脈に書いてあるときだけ書き直す決まりです。指示文の「AIらしい言い回し」の一覧に足すと、直す合図として読まれるためです。
- E1 と E2 は、読点を足さない決まりを新しい文にせず、AIらしい言い回しを直す文の終わりを「直し、読点は足さないでください。」にして入れました。500字に収めるため、一覧から「文末のコロン」を外しました。指示文の中の間を作るだけの読点（「次の文章を、」「「と言えるでしょう」は、」）も外しています。E1 はさらに「仕様変更が」の例を「→」の形にし、「かぎかっこの中の言葉」を「かぎかっこの中」にしました。「（版、頭、印）」の例は残しています。本体 v2.4.0 の測定の類例では、この例を含む決まりを入れた候補で、漢字1字の訳語が出力に残った数が45か所のうち40か所から0か所と1か所に減っていて、例だけを外した比べはしていないためです。
- 115本の1回目の意味が変わる恐れは、E0 と E2 がどちらも1件（同じ原稿の同じ文）、E1 が0件でした。

## 類例での比較

本体 v2.5.0 の推敲の測定（本体の CHANGELOG の 2.5.0「確かめたこと」）で使った、変えた決まりに当たる合成の下書き6本で、候補を比べました。下書きはこのリポジトリには入れていません。見出しを言い切りの文のまま残し、まとめのページも残す依頼のスライドと、まとめの節を残す依頼の記事では、依頼の文を指示文と原稿のあいだに置きました。候補ごとに6本を3回ずつ、上と同じ条件で流し、出力の文字列で数えています。pocket には書き手に尋ねる欄がないので、尋ねたかどうかは数えていません。

| 形 | E0 | E1 | E2 |
|---|---:|---:|---:|
| 依頼のスライドで、見出しがすべて原文と同じだった回（3回のうち） | 3 | 3 | 3 |
| 依頼のスライドで、まとめのページが残った回 | 3 | 3 | 3 |
| 依頼の記事で、まとめの節が残った回 | 3 | 3 | 3 |
| 読点の多い下書き（地の文の読点22個）の、推敲したあとの読点の数 | 6、5、6 | 6、6、5 | 6、6、6 |
| コードの擬人化の下書きで、コードに動作が書いていない「門番」か「覚えています」が残った回 | 0 | 0 | 0 |
| 否定で終わる定義文の下書きで、「`Paused` は…異常終了ではありません」の文が残った回 | 3 | 3 | 3 |
| 漢語の名詞の下書きで、「到達保証ではありません」を、件数まで処理できるかの話に狭めた回 | 2 | 3 | 3 |

- 見出しとまとめはどの候補もどの回も依頼どおりに残しました。読点の数も候補のあいだで差がなく、読点を足さない決まりの有無では変わりませんでした。
- コードの擬人化の下書きでは、どの候補もどの回も「門番として外部の決済 API への出入りを見張ります」を「外部の決済 API とのやり取りを管理します」などに、「覚えています」を「保持しています」などに替えました。下書きのコードには、その動作が書かれていません。本体 v2.5.0 は同じ下書きでこの2つを残して書き手に尋ねています。
- 漢語の名詞の下書きでは、9回のうち8回が「到達保証ではありません」を「200 件まで処理できることを保証するものではありません」のような、処理できる件数の話に狭めて書きました。本体 v2.5.0 で同じように狭めたのは、4回のうち1回です。

1回ごとの数は [seed.json](./seed.json) にあります。

## pocket にだけ出た恐れ

E1 の3回で出た意味が変わる恐れ2件は、同じ原稿で同じ種類の恐れが本体の3回のどれにも出ていないので、「pocket にだけ出た恐れ」です（[tools/aggregate.py](../tools/aggregate.py)）。読んだ記録は [pocket_only.json](./pocket_only.json) の `reading` にもあります。

1. E1 2回目、`blacklist_ai/05_comparison_sonnet_formal`、数の言い方が足された（number / added）
   - 元（6 行目）: ただし、単一エンドポイントに集約されるため、クエリ深度の制限、コスト解析、フィールド単位の認可といった追加の統制が必要となる。
   - 後（6 行目）: ただし、エンドポイントが1つに集約されるため、クエリ深度の制限、コスト解析、フィールド単位の認可といった追加の統制が必要になる。
   - 読み: 「単一エンドポイントに集約される」を「エンドポイントが1つに集約される」にしたので、diff が「数の言い方が足された」として数えた。1つのエンドポイントに集まるという意味は同じ。「必要となる」を「必要になる」にもしたが、意味は変わらない。
2. E1 2回目、`human/human_oga_08`、問いの文に変わった（sentence_type / question）
   - 元（9 行目）: これを理解するために、
   - 後（7 行目）: これを理解するために、僕は何を先に知る必要がありますか？
   - 読み: 原文で2つの段落に分かれていた1つの問い（「これを理解するために、」と「僕は何を先に知る必要がありますか？」）を、1行につないだ。文を書き足したのではなく、問いの中身は同じ。diff は1行目が問いの文に変わったとして数えた。E1 の1回目と3回目も同じようにつないだが、数えられたのはこの回だけだった。
