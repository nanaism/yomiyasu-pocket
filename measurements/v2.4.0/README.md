# 本体 v2.4.0 で測った結果

この記録は本体 v2.4.0 から指示文を作ったときの測定です。いまの指示文は本体 v2.5.0 から作り直し、[../README.md](../README.md) の測定で選びました。

本体（yomiyasu v2.4.0）と pocket の指示文に同じ文章を推敲させ、本体 v2.4.0 の検査で数えた結果です。このときの指示文は候補 D2 です。

本体 v2.2.2 から指示文を作ったときの測定は [v2.2.2/README.md](../v2.2.2/README.md) に、本体 v2.1.1 から作ったときの測定は [v2.1.1/README.md](../v2.1.1/README.md) にあります。指示文の決まりの多くは、そのときの比較で選んだものです。

## 条件

- 推敲させた道具: Claude Code 2.1.296（`claude --print`）
- モデル: claude-opus-5-5
- effort: high（`--effort high`）
- service_tier: Claude Code の記録では、どの回も standard でした。
- 本体と pocket で共通の設定: `--setting-sources project` で利用者の設定を読まず、`--settings '{"claudeMdExcludes":["**/CLAUDE.md","**/AGENTS.md"]}'` で CLAUDE.md と AGENTS.md を外し、`--strict-mcp-config --mcp-config '{"mcpServers":{}}'` で MCP のサーバーを外しました。`--no-chrome` と `--no-session-persistence` も付けています。1本ごとに空の作業場所を作り、1回の依頼で1本を推敲させました。
- 本体だけの設定: 使える道具を Bash、Read、Write、Edit、Skill にし（`--tools "Bash,Read,Write,Edit,Skill"`。Agent、WebFetch、WebSearch は `--disallowedTools` で外す）、`--permission-mode dontAsk`、`--max-turns 60`、`--max-budget-usd 5` で動かしました。
- pocket だけの設定: 道具をすべて外し（`--tools ""`）、`--max-turns 3`、`--max-budget-usd 2` で動かしました。

## 数え方

Claude Code の結果を [tools/run.py](../tools/run.py) と同じフォルダの形に並べ、[tools/score.py](../tools/score.py) と [tools/aggregate.py](../tools/aggregate.py) で数えました。

- 意味が変わる恐れ: 元の原稿と書き直した文を、本体 v2.4.0 の `yomiyasu_diff.py --fail-on meaning-risk`（文書の種類は指定しない）で比べた `fail_on_meaning_risk_count` です。
- 残った候補: 書き直した文を本体 v2.4.0 の `yomiyasu_lint.py` で調べた候補の数です（error、warn、info の合計）。括弧の中は warn と error だけの数です。元の原稿115本では50件です。
- 元のまま: 前後の空白を除いて、書き直した文が元の原稿と同じ文章の数です。
- 書き換えた量: `difflib.SequenceMatcher` の opcodes のうち、同じでない部分ごとに元と後の長いほうの字数を足し、元の原稿の空白を除いた字数1,000字あたりにした値です。`human/` の16本の中央値（小さい順に並べた9番目）を載せます。本体の2回目と3回目は、書き直した文のある15本の8番目です。

合格の線は、pocket の意味が変わる恐れの3回の合計が、本体の3回の合計を超えないことです。この測定を始める前に決めました。D2 は3回の合計が2件で、本体の4件を超えていません。本体 v2.2.2 の測定では1回ずつも比べましたが、この測定の合格の線には入れていません。1回ずつ見ると、D2 の1回目（2件）は、本体の2回目（1件）と3回目（0件）より多く出ています。

本体の4件は、`blacklist_ai/07_code_review_sonnet_casual` で2つ目の提案の「…見えないようにします」を「…見えないようにしてください」にした文の種類の変化が1件、`human/human_doc_16` で「週に1回木曜日に」を「毎週木曜日に」にして数の言い方が消えたもの（number / lost）が1件、`human/human_oga_04` で2行に分けて書かれた問いを1文につないだものが2件（1回目と2回目）です。

## pocket にだけ出た恐れ

D2 の3回で出た意味が変わる恐れ2件は、同じ原稿で同じ種類の恐れが本体の3回のどれにも出ていないので、「pocket にだけ出た恐れ」です（[tools/aggregate.py](../tools/aggregate.py)）。読んだ記録は [pocket_only.json](./pocket_only.json) の `reading` にもあります。

1. D2 1回目、`blacklist_ai/06_spec_draft_sonnet_default`、保証の言い方（promise / guarantee）
   - 元（7 行目）: 重複配信に備え、プロバイダのイベントIDで冪等性を担保する。
   - 後（7 行目）: 重複配信に備えて、プロバイダのイベントIDで冪等性を担保する。
   - 読み: 「備え、」を「備えて、」にしただけで、「冪等性を担保する」は元の文にも同じ形である。diff はこの文の保証の言い方（担保する）を確かめる所として数えたが、何を保証するかも言い切りの強さも変わっていない。
2. D2 1回目、`blacklist_ai/07_code_review_sonnet_casual`、数の言い方が消えた（number / lost）
   - 元（1 行目）: `OrderService.checkout` の中で、在庫テーブルへの直接クエリ、決済APIのHTTP呼び出し、割引計算のロジックが1メソッドに並んでいます。
   - 後（1 行目）: `OrderService.checkout` の中に、在庫テーブルへの直接クエリ、決済APIのHTTP呼び出し、割引計算のロジックが1つのメソッドに並んでいます。
   - 読み: 「1メソッド」を「1つのメソッド」にしたので、diff が「数の言い方が消えた」として数えた。3つの処理が1つのメソッドに並んでいるという意味は同じ。「の中で」を「の中に」にもしたが、意味は変わらない。
